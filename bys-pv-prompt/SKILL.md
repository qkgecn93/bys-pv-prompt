# 平面动画 PV 提示词导演

## 一、这个 Skill 在解决什么问题

一句话：**给抽象概念找画面。**

口播视频里最难配画面的从来不是"一个人在打字"，而是"信息过载""复利效应""个体与组织的博弈""时间在流逝"。这些东西实拍拍不到，图库里全是烂俗素材。

而平面动画 PV 风恰好是抽象概念的天然载体——它本来就用圆环、刻度、网格、剪影、几何切片说话。

还有一层不那么明显但很重要的原因：**这个风格的美学禁令，恰好是 AI 视频模型的能力边界。** 模型最不擅长物理一致性和连续复杂动作，而这个风格明令禁止写实运动、禁止三维透视、要求"以关键姿态和定格表现"。等于把模型的弱点变成了风格特征，成片率比写实 B-roll 高一个量级。

理解这一点，你才知道为什么下面那些"限制"不是束缚，是这个风格能跑通的原因。

---

## 二、风格的四层结构（决定了什么能换、什么不能动）

这套风格拆开是四层。搞清楚哪层能换，才能把它从"游戏 PV"迁移到新闻、故事、知识、商业任何题材：

| 层 | 内容 | 能不能换 |
|---|---|---|
| **L1 渲染语法** | 硬边赛璐璐、纯色填充、剪影、阴影只 1–2 层、3–5 色高反差、无景深 | **锁死** |
| **L2 图形语汇** | 圆环、刻度、网格、扫描线、网点、几何切片、UI 框线、斜向色块 | **锁死** |
| **L3 动效语汇** | 反相、遮罩擦除、图形匹配、单帧闪白、纸片翻转、Glitch、圆形扩散 | **锁死** |
| **L4 题材符号** | 该题材的具体物件（新闻＝人形阵列/地图轮廓，商业＝齿轮/天平，故事＝门框/路灯） | **每次都换** |

**"游戏感"几乎全部集中在 L4。** 换掉 L4，L1–L3 一字不动，风格依然成立——这是这个 Skill 能覆盖新闻、故事、知识题材的全部依据。

L1–L3 合称**风格锁**，一次确定后**逐字复制**到每一段提示词里。不能写"同上"，不能改写——模型没有跨次生成的记忆，每一段都是从零开始。

L4 符号库按题材换血，以及任何真实场景的平面化通法（抽 3–5 个标志性构件 → 线稿 + 色块 + 网格），见 `references/concept-map.md`。

## 三、主流程

七步。每一步都写了**失败了怎么办**——AI 视频这行的常态是跑一次不满意，只有正向路径的流程等于只能用一次。

### Step 1 · 判断模式

| 用户给了什么 | 判定 |
|---|---|
| 音频文件 / SRT / "对齐我的口播" | **模式 B** |
| "让模型自己配音""带声音""一次出成片" | **模式 A** |
| 只给主题、观点或稿子，没提配音 | **模式 C** |

🔴 **CHECKPOINT** —— 模式决定全部产出格式（B 要分镜总表，A 要旁白块，C 都不要）。判据不落在上表任何一行 → **停下来问，不要猜**。猜错的代价是整包重出。

### Step 2 · 收集参数 🔴 **CHECKPOINT**

用 AskUserQuestion 一次性问全七项，不要挤牙膏。缺任何一项都会返工：

| # | 参数 | 默认值与说明 |
|---|---|---|
| 1 | 目标模型 + 单段时长上限 | **必问，不许凭记忆假设。** 各家上限差异大且变动频繁 |
| 2 | 模式 | Step 1 已判定，此处向用户确认 |
| 3 | 题材类型 | 新闻/科技/商业/故事/知识/心理 → 决定 L4 符号库 |
| 4 | 动效密度 | **由用途决定，不由风格形容词决定**（见下）|
| 5 | 画幅 | 16:9 / 9:16 / 1:1 |
| 6 | 配色主题 | 默认冷蓝都市；6 套预设见 `references/style-lock.md` |
| 7 | 是否要角色 | 默认无面剪影，理由见 §八 |

**如果用户答不上模型上限** → 拿 `references/modes.md` 的参考表给他对照；仍不确定则按 **8 秒**出，并在交付时标注「按 8 秒保守值切段，你的模型若支持更长可合并相邻段」。不要自己替他选一个长值——超上限的提示词等于全废。

**动效密度只看用途，不看风格形容词。** 用户说"要游戏 PV 感""要炸""节奏快"，指的是**美术风格**，不是要你把垫在人声下的 B-roll 提到 PV 密度。判据只有一条：

| 这支片播放时，有没有人声压在上面？ |  |
|---|---|
| 有（B-roll、垫片、配口播） | **低密度 0.5–0.8 /s** 锁死，每段只做 1–2 个图形动作 |
| 没有（独立短片、片头、纯画面素材） | **高密度 2.0+ /s**（15 秒约 30 画面，爆发段 3/s）|

实测翻车：模型自己写下"标准 B-roll 是 0.5–0.8 切/秒"，又以"用户要 PV 感"为由上调到 1.4。**风格词不是密度授权。** 用户真要高密度 B-roll，让他明说"我知道会抢人声"再改。

### Step 3 · 内容切段

切段算法（含 4.5 字/秒常数、合并与拆分规则）见 `references/modes.md`。

- **如果口播稿没标点或结构散** → 先按语义重新断句，再切段。按字数硬切会把一个概念劈成两半。
- **如果某个语义单元找不到对应画面** → 查 `references/concept-map.md` 下层表；仍找不到，说明这个概念太具体（§八），**标注出来问用户**，不要硬编一个牵强的图形。

### Step 4 · 建风格锁

按 Step 2 的配色 + 题材，从 `references/style-lock.md` 取模板，填出【画面】【动效要求】两块。**这两块此后一字不改。**

### Step 5 · 逐段拼装

每段 = 声明句 + 风格锁（逐字复制）+ 该段【镜头节奏】+ 音频块（模式 A）。分镜写法见 §六六条铁律。

- **如果段数 > 12** → 提醒用户分批生成，并强制附锚点帧方案（§七）。段数一多，不用锚点帧风格必漂。
- **如果单段密度压不上去（模型糊成闪烁）** → 不要继续加码，改走分段生成再拼；每段任务简单，实际达成密度反而更高。

### Step 6 · 自检 🔴 **CHECKPOINT**

按 §九清单逐条过。**任一项不过 → 回到对应 Step 重出，不要带病交付。** 这个风格的失败是系统性的（一个渐进性动词就能拖慢全片），不是交付后再打补丁能救的。

### Step 7 · 交付

顺序固定：**分镜总表（模式 B/C）→ 每段完整提示词 → 一致性落地建议（§七）**。总表必须在最前——用户拿到一堆提示词却不知道哪段配哪句，等于没交付。

**每段提示词用代码块整段包裹**，一段一块——靠标题和分隔线划边界，用户复制时会把标题也带进去。前言压到 5 行内。

- **如果用户反馈"节奏慢 / MG 感不够"** → 这是最高频的失败反馈。查 `references/shot-writing.md` 的失败模式速查表定位病因（九成是渐进性动词泄漏或双轨没解耦），**不要笼统地"再改快一点"**。
- **如果用户反馈"跑出来不像那个风格"** → 先查风格锁是否被逐字复制，再查是否有三维用词泄漏。

### 兜底速查（一线修复已写在各 Step 内，这里只列**仍失败时的升级动作**）

| 一线修复无效时 | 兜底 |
|---|---|
| 节奏慢 / MG 感不够 | 删掉旁白改走模式 C，后期 TTS 另配——没有句子边界拖着，节奏是全片上限 |
| 密度压不上去、糊成闪烁 | 先把 15 秒档从 30 镜降到 24–26 镜；仍糊则弃单次生成，改分段 + 锚点帧 |
| 多段风格漂移 | 上锚点帧；支持多图参考的模型（如 H3 九图位）上风格图板 |
| 中文人声合成翻车 | 删旁白段只留音乐，配音后期 TTS |
| 剪影长出会动的嘴 | 补「不需要口型」那句仍复发 → 改用纯图形无角色版本 |
| 题材需要真实物件辨识度 | 不要硬套，直接劝退（§八），建议实拍或图生视频 |

## 四、三种模式

### 模式 A · 台词写进提示词，模型自带配音

只有原生音频模型能做（MiniMax H3 / Veo / Sora / Seedance 2.x）。

**中文人声合成目前普遍不稳**（断句、语速、口音都可能翻车）。但在这个风格里这不是致命问题——角色是无面剪影，本来就没有嘴，做的是画外音旁白不是对口型。所以提示词里必须写死这一句：

> 「旁白为画外音，画面中没有任何人物开口说话，不需要口型，不出现说话的嘴部特写。」

不写的话模型会自作主张给剪影加一张会动的嘴，风格直接毁掉。这是实测踩过的坑。

如果旁白质量不能用，退路是：删掉旁白段只保留音乐，配音后期用 TTS 另配。

### 模式 B · 按口播音频对齐

**这里有一个必须纠正的常见误解**：主流文生视频模型**不接受"音频驱动画面节奏"**。能吃音频输入的模型（如 H3 的音频参考位）用途是音色参考或数字人口型，不是让 MG 图形卡上你的鼓点。

所以"对齐"的正确实现是**用时间码，不是用音频文件**：

```
口播音频 → 转录成带时间码的 SRT → 按语义+时间码切段
        → 每段提示词带精确 in/out 时长 → 用户在剪辑软件按时间码摆
```

这条路能真跑通，而且精度比"让模型对齐"高——时间码是确定的，模型对齐是玄学。

**切段规则**（详见 `references/modes.md`）：按语义单元切，不按固定秒数切。中文口播约 **4.5 字/秒**，可用于从字数反推时长。超模型上限就在句号或转折处拆；不足 3 秒就与相邻段合并（单镜低于 3 秒观众来不及读画面）。

### 模式 C · 只出画面

最简单。主题 / 关键词 / 一段文字 → N 段独立提示词。适合攒素材库。

**顺带一提**：C 模式天然比 A 模式节奏快，因为没有旁白的句子边界拖着画面走。如果用户对节奏要求极高，纯画面 + 后期 TTS 是保上限的做法。

## 五、输出格式

严格用这五块，顺序不变。这是从三份成熟参考里抽出的公因式，块头用【】：

```
（声明句：时长 / 画幅 / 媒介 / 原创声明）
【音乐】   ← 模式 A 写全；B/C 至少留一句音乐氛围，**不能整块省略**
【画面】   ← 风格锁 · 逐字复制：配色 + 渲染方式 + 元素库 + 角色
【镜头节奏】← 每段可变：首句写本段密度数字，其后是短句流分镜
【动效要求】← 风格锁 · 逐字复制：允许的动作 + 双轨解耦 + 避免清单
```

完整可填空模板在 `references/style-lock.md`。

**密度句写【镜头节奏】首句，不写【动效要求】**——理由和写法见 §六铁律 3。单段成片不受此限。

**【音乐】不能裸省。**【动效要求】写着"转场跟随鼓点"，鼓点从【音乐】块来——省掉它等于让模型跟一个没给过的鼓点（实测翻过车）。B/C 至少留一句"132BPM 冷调电子，鼓点稳定推进，本段不做收束"；真不要音乐就把"跟随鼓点"改成"按等间隔硬切"。

### 画面内文字：默认全部后期加

AI 视频模型渲染中文几乎必糊。

- **中文一律不进提示词**。要出字的地方（标题、店名、落款）在分镜里写成**空白框位**（"米白色矩形框，框内留空"），后期打字，反而更利落。
- **英文可以有但要极简**——单词级（`COST`/`WHY`/`FINAL`），每支片不超过两处。参考 PV 就是这么做的。
- 每次交付**主动提示这条**，别等用户跑糊了才说。

## 六、分镜写作的六条铁律

**这是整个 Skill 最值钱的部分。** 每一条都是实测翻车换来的——同样的风格锁、同样的题材，写法不同能差出三倍节奏。

### 1. 动词决定速度

这是提速的第一杠杆，比任何"节奏要快"的形容词都有效。

| 慢（渐进性，禁用） | 快（瞬间性，只用这些） |
|---|---|
| 生长、展开、浮现、逐渐形成、缓缓移动、慢慢转变 | 弹开、劈入、闪现、划过、反相、碎裂、塌缩、拼合、炸开、掠过、切入 |

写「细线自头顶向上生长，逐级展开」——慢在词性里，后面加多少"硬切"两个字都救不回来。
写「色块从地面弹开」「刀尖划过画面」「怪物剪影闪现」——不用说"节奏快"，它就是快的。

### 2. 分镜写成时间段内的短句流，不写编号清单

正确的样子（一个时间段 5–8 个短句，**句号就是剪辑点**）：

> 3–6秒：白色连线一次性铺满整张网。人形剪影阵列高速填入网格，矩形方块分裂成三组各自对齐，齿轮线稿与圆环叠加咬合旋转。画面蓝白反相一帧。俯视网格被黑色斜向色块横穿，切成多个不规则区域；刻度数字在特写中高速滚动。

四句话装了七个画面。密度来自句子密度，不需要编号。

**为什么不能写编号清单**：视频模型的训练数据是自然语言画面描述，不是结构化列表。写成「01 剪影入画 / 02 特写肩线 / 03 闪白」大概率被当成元信息而非画面内容。这条是实测中把提示词从散文改成清单后节奏反而变差得出的。

### 3. 密度给数字，用散文句，写在【镜头节奏】首句

「节奏快」模型听不懂，「本段共 6 个画面，平均每零点五秒切换一次」听得懂。

两点必须同时做到，缺一条就白写：

- **用散文句**，不要单起一个"最高优先级"的元指令块——参考里没有的东西一律不加。
- **写在【镜头节奏】每段首句**。【动效要求】是要逐字复制的风格锁，密度却要按段爬坡（参考 PV 是开场 1.0/s、中段 1.7/s、高潮 2.7/s），塞进同一块必然打架。实测翻车过：解说写着"这段顶到 2.2 切/秒"，六段【动效要求】却字节相同全写 0.8 秒——**密度只活在解说里，没进真正粘贴给模型的提示词**。

爬坡参考值：开场 1.0/s、中段 1.7/s、高潮 2.3–3.0/s（超 2.3 有糊成闪烁的风险）、B-roll 0.5–0.8/s。逐镜实测数据见 `references/shot-writing.md`。

### 4. 台词轨与镜头轨必须解耦

**有旁白就有句子边界的引力**，不显式掰开，模型会把一句话读成一个场景单元，切点全落在句尾——出来就是配旁白的 PPT。

在【动效要求】里写死：

> 「画面剪辑点只跟随鼓点，不跟随旁白的句子边界，一句旁白横跨七到八个画面，允许在句子中间切换画面；严禁一句台词对应一个画面。」

**免费的密度**：并列结构一个词一刀。「招人、分工、协调」= 三个画面，台词一个字没加。

### 5. 模式 A 要留爆发窗口

参考 PV 全是纯音乐音效、没有一句旁白，所以画面能完全跟鼓点走。旁白一旦铺满，模型会拉慢画面等台词。

**文案按时长打八折**（15 秒写 50–55 字而非 65 字），中段留 2–3 秒纯音乐窗口给画面发力。这也符合 PV 本身的结构——参考都是"若干秒后鼓点进入，后段蒙太奇爆发"。

### 6. 动效密度分场景，不一刀切

档位判据在 Step 2。参考 PV 的"快速 MG 蒙太奇"放进 B-roll 是灾难；选错这条，前五条做对也白搭。

---

## 七、跨段一致性

一支 3 分钟口播要切 15–25 段，独立生成还要像同一支片。三个手段叠加：

1. **风格锁逐字复制** —— 一字不改地贴进每一段。这是底线。

   风格锁**只包含三样**：声明句（除时长外）、【画面】整块、【动效要求】整块。
   **不包含**：【镜头节奏】、密度句、【音乐】块里的段落位置描述——这三样本来就该按段变。
   分不清哪些该变哪些不该变，是多段生成翻车的头号原因。
2. **锚点帧** —— 先生成第 1 段，抽一帧当基准，后续段走图生视频（Seedance / Kling / H3 都支持首帧图）。提升最明显的一招。
3. **参考图板** —— 支持多图参考的模型（如 H3 可喂 9 张），先用图像模型出一套风格板全程复用。

产出提示词时要**主动附上这三步的操作建议**，而不只是甩一堆提示词。

---

## 八、角色与劝退

**角色默认不要**——20 段保持同一张脸成本极高。折中用**无面黑色剪影**（只有肩线与头部轮廓，无五官），并给它可特写的部位：肩线边缘、胸口、手部，景别层次就回来了。完整取舍见 `references/style-lock.md`。

**该劝退就劝退**：需要具体真实物件辨识度的内容（某款手机、某道菜、某个地标、某个真人）平面化后辨识度归零，老实建议实拍或图生视频。完整不适用清单见 `references/concept-map.md`。

---

## 九、自检清单

出稿后逐条核对：

- [ ] 风格锁三样（声明句 / 【画面】/【动效要求】）是否**逐字**出现在每一段，没有"同上"
- [ ] **密度句是否在【镜头节奏】首句而非【动效要求】里**；档位是否按"有无人声压着"定而不是被"要 PV 感"带偏；解说里声称的密度变化，是否真的落进了各段提示词
- [ ] **提示词里有没有中文文字要模型渲染**——有就改成空白框位，并提示用户后期加
- [ ] 【音乐】块是否还在（哪怕一句）；若已省略，【动效要求】里的"跟随鼓点"是否同步改掉
- [ ] 每段提示词是否用代码块整段包裹，边界干净可直接复制
- [ ] 分镜里有没有渐进性动词泄漏（生长 / 展开 / 浮现 / 逐渐 / 缓缓）——低密度段同样不许。要"呼吸感"就用「高速旋转一圈后定格」这类瞬间动词达成，**绝不为此改动风格锁**
- [ ] 分镜是短句流还是编号清单
- [ ] 有没有三维用词泄漏（景深 / 透视 / 立体 / 推近 / 3D / CG）
- [ ] 模式 A：是否写了"画外音、不需要口型"；是否留了爆发窗口；文案是否打过八折
- [ ] 台词轨与镜头轨解耦那句是否写进了【动效要求】（仅模式 A/B 有旁白时；模式 C 不写）
- [ ] 每段时长是否在用户给的模型上限内
- [ ] 原创声明（不出现真实 Logo / 真人 / 现成 IP 素材）是否每段都在
- [ ] 动效密度档位是否与场景匹配
