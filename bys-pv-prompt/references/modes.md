## 2. 切段算法

**核心原则：按语义单元切，不按固定秒数切。** 一个语义单元 = 一个可被单独可视化的概念。

**实用常数：中文口播约 4.5 字/秒**（正常语速）。用于从字数反推时长。注意实际朗读带停顿会更慢，估算偏保守一点更安全。

```
1. 口播稿 → 切成概念单元（在语义转折、话题切换、并列项之间切）
2. 每单元字数 ÷ 4.5 = 估算时长
3. 若 > 模型单段上限 → 在句号或转折处拆成两段
4. 若 < 3 秒 → 与相邻单元合并
   （单镜低于 3 秒观众来不及读画面，这个风格信息密度高，更要留时间）
5. 输出分镜总表：段号 / 对应口播原文 / in-out 时间码 / 目标时长 / 画面概念
```

**为什么不按固定秒数切**：固定切会把一个概念劈成两半，出来的两段画面各说各的，观众看不懂。宁可段长不均匀。

## 3. 模式 A · 台词内嵌，模型自带配音

**适用**：短片、片头、完整的小段落。**不适用**：长口播（旁白质量风险随时长放大）。

```
1. 确认模型支持原生音频（H3 / Veo / Sora / Seedance 2.x）
2. 写文案 —— 按时长打八折（15 秒写 50–55 字，不是 65 字）
3. 排台词时间轴，中段留 2–3 秒纯音乐爆发窗口
4. 分镜按自己的节奏走，密度独立于台词
5. 【音乐】块写全：BPM / 曲风 / 音效 / 旁白段（含"画外音、不需要口型"）
6. 【动效要求】写死双轨解耦声明
```

**必写的两句**（逐字）：

> 旁白为画外音，画面中没有任何人物开口说话，不需要口型，不出现说话的嘴部特写。

> 画面剪辑点只跟随鼓点，不跟随旁白的句子边界，一句旁白横跨七到八个画面，允许在句子中间切换画面；严禁一句台词对应一个画面。

**交付时要提示的退路**：中文人声合成目前普遍不稳。如果旁白不能用，删掉旁白段只保留音乐，画面单独出，配音后期用 TTS 另配——这条退路同时也是节奏上限最高的做法。

## 4. 模式 B · 按口播音频对齐

### ⚠️ 先纠正一个常见误解

主流文生视频模型**不接受"音频驱动画面节奏"**。能吃音频输入的模型（如 H3 的音频参考位、OmniHuman 系）用途是**音色参考**或**数字人口型驱动**，不是让 MG 图形卡上鼓点。而且 OmniHuman 那条路产出的是写实数字人，与本风格对立。

用户说"把音频传给模型对齐"时，要主动说明这一点并给出可行方案，不要假装能做。

### 可行的实现：用时间码对齐

```
用户提供口播音频
  ↓
转录成带时间码的 SRT（用户已有就直接用；没有就提示先转录）
  ↓
按语义 + 时间码切段（见第 2 节算法）
  ↓
每段提示词标注精确 in/out 与目标时长
  ↓
用户在剪辑软件里按时间码摆
```

精度比"让模型对齐"高得多——时间码是确定的，模型对齐是玄学。代价是用户要做一次剪辑摆放，但这本来就免不了。

### 产出物

1. **分镜总表**：段号 / 时间码 / 口播原文 / 目标时长 / 画面概念
2. **每段完整提示词**（风格锁逐字复制）
3. **落地操作建议**（锚点帧、参考图板）

分镜总表要放在最前面。用户拿到一堆提示词却不知道哪段配哪句，等于没交付。

## 5. 模式 C · 只出画面

**适用**：攒素材库、通用垫片、不确定配哪段口播时先做储备。

```
1. 从主题 / 关键词 / 一段文字里提炼 N 个概念单元
2. 每个概念单元查 concept-map.md 两层表
3. 出 N 段独立提示词
```

**C 模式天然比 A 模式节奏快**，因为没有旁白的句子边界拖着画面走。用户对节奏要求极高时，建议走 C 模式 + 后期 TTS，这是保上限的做法。

**建议一次出 6–8 段**成组交付，配色和元素库统一，用户可以按需取用。

## 6. 一致性落地三步

多段生成时必须附上这三条建议，否则用户拿到提示词跑出来会是风格各异的碎片：

**① 风格锁逐字复制**
三样（声明句除时长外 / 【画面】整块 / 【动效要求】整块，禁令写在动效要求末尾）一字不改贴进每一段。不能写"同上"——模型没有跨次生成的记忆。这是底线。

**② 锚点帧**
先生成第 1 段，从中抽一帧当视觉基准，后续段走**图生视频**（首帧图）。一致性提升最明显的一招，成本几乎为零。

**③ 参考图板**
支持多图参考的模型（H3 可喂 9 张）：先用图像模型出一套 6–9 张风格板（配色卡 + 典型构图 + 若有角色则加三视图），全程复用。

**分段生成还有一个副作用是好的**：每段任务简单，模型执行力更强，实际达成的镜头密度反而比单次长生成更高。如果单次生成压密度压不上去，直接改走分段路线，不要在单次生成上较劲。
